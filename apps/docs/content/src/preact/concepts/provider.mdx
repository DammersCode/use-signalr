Without `onError`, the provider drops errors silently.

A token change needs no rebuild. The library calls `accessTokenFactory` again when it needs a token. Do not use the token as `connectionKey`, or each refresh rebuilds all hubs. Use a user ID or a login counter.

## When the connection starts and stops

The provider starts the session in `useEffect`. Effects do not run during server rendering, so server rendering opens no connection. Every hub reports `idle` until the first effect runs in the browser.

After that effect, an eager hub connects. A lazy hub connects when its first consumer mounts.

The provider applies `baseUrl`, `enabled`, and `connectionKey` again when one of them changes. A change of any of the three stops all connections. When `enabled` is not `false` and `baseUrl` is set, the provider then starts them again. A hub that was connected reruns its reconnect callbacks after the rebuild.

When the provider unmounts, the session stops all hubs. A change of a prop does not stop the session for good.

## Latest props

The provider reads the latest `accessTokenFactory`, `onStatusChange`, and `onError` on each call. A new function on each render does not rebuild a connection. It also does not need `useCallback`.

Only `baseUrl`, `enabled`, and `connectionKey` act as triggers. The provider compares them by value.

## preact/compat

The provider imports `preact` and `preact/hooks` only. You do not need `preact/compat` or an alias for `react`.

## Errors from wrong placement

A hook that runs outside the provider of its client throws. [Troubleshooting](/docs/preact/reference/troubleshooting) has the message and the cause. Each client has its own context. Use the hooks and the provider from the same `createSignalRClient` call.
